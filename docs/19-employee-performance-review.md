# 직원 평가와 근거

## 1. 목적

성과를 검토하고 역할·모델 선택을 개선한다. AI 평가 문장은 객관적 사실이 아니라 근거를 확인할 수 있는 의견이다.

## 2. 범위

Phase 4에 PEER/SELF/PM/USER/AUTO 유형을 분리한다. 자동 품질 지표와 AI/사람 의견을 확정 사실로 혼합하지 않는다.

## 3. 요구사항

| 항목 | 초기 가중치 | 근거 예시 |
|---|---|---|
| 정확성 | 0.30 | 수용 기준·잘못된 변경 |
| 결과물 품질 | 0.30 | 테스트·리뷰·유지보수 판단 |
| 협업 | 0.20 | 인계 완전성·범위·근거 |
| 효율 | 0.20 | 성공 작업당 비용·시간·재작업 |

항목별 0~100, 가중치 합=1. 총점=`정확성×0.30+품질×0.30+협업×0.20+효율×0.20`. 가상 80/90/70/60이면 `24+27+14+12=77점`. 실제 직원 결과가 아니다. 가중치/rubric은 버전 관리하고 과거 점수를 조용히 재계산하지 않는다.

## 4. 설계 내용

대상/task/run 근거·평가자·유형·rubricVersion·점수/가중치·영어 원문·한국어 요약·evidence refs·상태를 저장한다. USER 한국어 원문은 original_ko에 보존하고 필요한 영어 파생본을 별도 저장한다. PEER/SELF/PM은 reviewer agent 필수, USER는 reviewer user 필수, AUTO는 system으로 두며 두 FK를 비운다.

정량 지표와 의견 점수는 별도 열로 표시한다. 미실행/표본 부족/근거 누락은 0점이나 평균 대입 대신 평가 불가다. 필수 항목을 평가하지 못하면 score=null, DRAFT/INVALID로 두고 PUBLISHED는 점수와 유효 근거를 요구한다.

## 5. 기술적 근거

원문 8장의 가중치·근거·편향/루프 안전장치를 따른다. 동일 모델 편향·상호 점수 부풀리기를 완전히 제거했다고 주장하지 않는다.

## 6. 데이터 흐름

종료 task의 증거 snapshot → 자기/동료/PM의 제한된 평가 → schema/근거 검증 → 한국어 요약 → Owner 검토/이의 제기 → 역할/모델/기간별 집계. 실패 task의 비용·재작업·오류도 포함해 성공한 것만 선택하는 편향을 피한다.

각 주장에 PR·test·AC·인계 Artifact를 연결한다. 원격 PR 증거는 SHA·조회 시점·검증 메타데이터를 보존한다. AI 원문은 영어, 사용자 평가 원문은 한국어 보존이 우선이다.

## 7. 예외 처리

task/대상/평가자/유형당 하나의 유효 평가만 허용하며 수정 이력을 보존한다. 초기 제한은 유형별 생성 1회·수정 1회다. 평가의 평가를 반복하는 루프는 금지한다. 근거 손실/충돌은 INVALID/NEEDS_REVIEW로 표시하고 Owner가 판단한다.

## 8. 보안 고려사항

점수로 자동 해고·권한 상승·예산 확대하지 않는다. 동일 모델 여부를 표시하고 필요 시 다른 모델/Owner 검토를 추가한다. 상호 고득점과 낮은 자동 품질의 불일치는 검토 대상으로 표시하되 조작으로 단정하지 않는다. 근거 조회도 조직/프로젝트 권한을 검사한다.

## 9. 구현 우선순위

자동 지표/근거 → 분리된 5유형 → 요약/Owner 검토 → 역할별 집계. 고급 분석과 모델 추천은 Phase 5 이후 평가한다.

## 10. 완료 기준

근거 없는 PUBLISHED 거부·점수/가중치 검증·유형 분리·편향 표시·loop 제한·Owner 수정/검토·퇴사 후 이력 보존을 시험한다.

## 11. 미확정 사항

상세 rubric·최소 표본·지표 정규화·평가 비용 한도는 데이터로 정한다. 난이도/역할이 다른 점수를 무조건 하나의 순위로 합치지 않는다.
