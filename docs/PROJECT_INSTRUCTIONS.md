# 프로젝트 지침

## 목적과 적용 범위

AI Pixel Company는 실제 저장소 변경·테스트·검토를 수행하는 AI 조직이다. 사용자는 Owner이며 최종 의사결정권자다. 초기 산출물은 설계·지침이었다. 2026-10-19 사용자 지시로 Phase 0 구현·실제 검증·지정 GitHub 저장소 push까지 범위가 확장되었다. 후속 Phase와 위험 작업 승인은 별도로 관리한다.

입력 기준은 사용자가 전달한 통합 마스터 프롬프트 v2.0의 네 첨부다. 처음 세 첨부의 17→22장 사이 누락은 추가 첨부의 18~21장으로 보완했다. 추가 첨부의 22장 끝부분은 잘려 있으므로 작업 규칙은 세 번째 첨부의 완전한 30개 규칙을 적용했다. 서로 상충하는 내용은 발견되지 않았으며, 제공되지 않은 내용을 원문으로 꾸미지 않는다.

## 우선순위와 산출물

실제 실행 정확성 → 결과 검증 → 권한·비용 통제 → 이벤트 관측 → 픽셀 표현 순서로 개발한다. B단계를 먼저 완성하고 같은 식별자·상태·이벤트·권한 계약으로 C단계에 확장한다. 사용자에게 보이는 상태는 한국어, 내부 식별자는 영어다.

지정 파일은 [INDEX](INDEX.md)를 따른다. 문서에 있는 JSON·표·그림은 계약 예시이며 실행 코드가 아니다. Phase 체크박스는 구현과 증거가 있을 때만 완료한다.

## 설계 기준

| 항목 | 규칙 |
|---|---|
| 상태 기준 | PostgreSQL 도메인 상태, 낙관적 version과 조건부 전이 |
| 큐 | Redis/BullMQ는 전달·스케줄링용, 영구 상태의 기준이 아님 |
| 실행 | LangGraph는 판단·체크포인트, Sandbox는 실제 파일·명령 실행 |
| 이벤트 | 도메인 변경·이벤트·outbox를 같은 DB 트랜잭션으로 기록 |
| 외부 부작용 | operationId로 기록하고 재시도 전 원격 상태를 조정 |
| 완료 | 수용 기준·변경 SHA·테스트·빌드·QA·승인 근거가 모두 유효 |
| 안전 | 기본 거부, 역할별 도구, 고위험 실행 직전 승인 재검사 |
| 비용 | 호출 전 예산 예약, 호출 후 정산, 미확정 사용량도 예약 유지 |
| 언어 | 한국어 원문 보존, 영어 협업, 필요한 사용자 보고만 한국어 |

## 변경 절차

요구사항 ID 부여 → 기존 설계와 관계/영향 확인 → 공수/Phase 판정 → ADR 및 문서/체크리스트 수정 → 필요한 승인 → 구현 → 검증. 구조·안전 경계가 충돌하면 근거와 대안을 먼저 제시한다. 직원 추가나 평가 점수로 권한을 자동 상승시키지 않는다.

위험 작업은 merge, 운영 배포, 운영 DB 삭제, 결제, 유료 증설, 민감 권한 변경, 고위험 도구 부여다. 승인에는 수행자·대상·SHA/내용 해시·범위·만료·예산을 묶고 단일 사용으로 관리한다. Slack 승인도 웹과 같은 신원·권한 검사에 종속된다.

## 검증·보고 및 한계

✅ 확인 사실, ⚠️ 설계 가정/미실증, ❌ 근거 없는 주장을 구분한다. 외부 기술 사실은 공식 문서 링크·열람일을 표시한다. 계산은 산식과 가정을 남긴다. 공식 문서에 기능이 존재한다는 사실과 이 프로젝트에서 동작한다는 주장을 분리한다.

실패·미실행·검증 불가를 누락하지 않는다. 최종 보고는 개요, 생성 파일, 아키텍처, 직원 시스템, 로드맵, 위험, Phase 0 판정, 다음 작업 순서로 작성한다. 비밀 값·원시 음성·전체 내부 대화는 사용자 보고에 무분별하게 포함하지 않는다.
